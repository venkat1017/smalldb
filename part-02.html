Pages: The Unit of Disk I/O

Part 1 proved that a database can be a file with rules. Now we deliberately make that design uncomfortable. Direct byte offsets are scattered through the storage code, every operation knows too much about the file, and there is nowhere to cache reusable data. We will solve that problem by putting one abstraction between the database and the file: the pager.

How to use this chapterDo not jump to the complete source at the end. Keep your editor and terminal side by side. We will preserve the Part 1 project, create a Part 2 workspace, and then build the pager in small pieces. At each checkpoint, stop and predict what the program should do before you run it. The goal is not to memorize pager code. The goal is to understand why databases stop thinking in arbitrary byte ranges and start thinking in pages.

1. Project setup: preserve Part 1 before changing the format

2. The pain we earned in Part 1

Part 1 was intentionally primitive. A record ID became a byte offset using one formula, and methods called ReadAt or WriteAt directly. That was an excellent first design because you could see the bytes. But now imagine the database growing features.

Suppose later we add a B-tree. A B-tree node must live somewhere in the file. Then we add free-space tracking. That metadata must live somewhere too. Then we want to cache frequently used pieces of the database in memory. Then we need to know which cached pieces changed and must eventually be written back. If every layer performs arbitrary file reads and writes, every layer becomes responsible for disk policy.

Part 1 question

“At what byte offset is record 37?”

The record layer knows the file layout and talks directly to os.File.

Part 2 question

“Which page contains record 37, and where inside that page is its slot?”

The pager owns file I/O. Higher layers manipulate memory buffers.

The second question looks like extra work. At first, it is. We are introducing an abstraction that our tiny database does not strictly need. The payoff is that all future disk access gets one doorway.

Store
records, IDs, tombstones
→
Pager
pages, cache, dirty state
→
os.File
bytes on persistent storage
Why not rely only on the operating system's file cache?The operating system already caches file data, but the database still needs its own logical unit of storage. Our pager must know which bytes form one database page, which pages have changed, which page number a B-tree node refers to, and eventually which pages may be evicted or pinned. The OS cache does not understand those database-level meanings.

3. What exactly is a page?

A page is a fixed-size chunk of the database file that our database chooses as its unit of I/O and organization. For this project, one page is 4096 bytes.

Do not turn “4096” into magic. Different storage engines make different choices, and hardware and operating systems have their own block and memory-page concepts. Our database page is simply a design decision: MiniSQLite Part 2 will reason about the file in 4096-byte chunks.

PageSize = 4096 bytes page 0 begins at byte 0 page 1 begins at byte 4096 page 2 begins at byte 8192 page 3 begins at byte 12288

The byte offset of a page is therefore:

pageOffset = pageNumber × PageSize

Compare this with Part 1. There, many database operations cared about exact record byte offsets. In Part 2, only the pager needs the page-to-file equation. The store will ask for page 7 and receive a 4096-byte buffer.

Teacher checkIf I ask for page 6, what byte offset should the pager read from? Work it out before continuing: 6 × 4096 = 24576. This is the only file-offset calculation we want the pager's clients to forget about.

4. Design the Part 2 file format before writing Go

We still have 256-byte records from Part 1. Keeping that size for one more chapter is useful because it lets us isolate the new idea. We are changing how records are grouped and accessed, not redesigning variable-length records yet.

Because 4096 / 256 = 16, exactly sixteen records fit in one data page.

Therefore we must persist some metadata—here, nextID—to know how far the logical record sequence has progressed.

5. Derive record-to-page math on paper first

Before we write a function, derive the mapping. There are 16 record slots in each data page. IDs start at 1, but division is easiest when counting from zero, so first convert an ID to a zero-based record index:

zeroBased = id - 1 pageNumber = 1 + zeroBased / 16 slot = zeroBased % 16 offsetInPage = slot × 256

TYPE 1Put the page and record constants in their own layers

In pager.go, begin with the storage unit:

package main

const PageSize = 4096

In store.go, add the record-layer constants:

package main

const (
    HeaderPage    = uint64(0)
    FirstDataPage = uint64(1)
    RecordSize    = 256
    MaxNameLen    = 32
    MaxEmailLen   = 64
    SlotsPerPage  = PageSize / RecordSize
)

Notice the ownership. PageSize belongs to the pager. RecordSize and SlotsPerPage belong to the store. The pager should not know that its bytes happen to contain users.

TYPE 2Encode the mapping once

Add this helper to store.go:

func recordLocation(id int64) (uint64, int, error) {
    if id < 1 {
        return 0, 0, ErrNotFound
    }

    zeroBased := uint64(id - 1)
    pageNum := FirstDataPage + zeroBased/uint64(SlotsPerPage)
    slot := zeroBased % uint64(SlotsPerPage)
    offset := int(slot) * RecordSize
    return pageNum, offset, nil
}

Do not scatter this arithmetic into Insert, Get, and Delete. A file format becomes maintainable when important layout rules have one source of truth.

6. Build the smallest useful Page type

A page in memory needs three facts:

  • which page number it represents,
  • its 4096 bytes,
  • whether those bytes differ from what is currently persisted.

Add to pager.go:

type Page struct {
    Number uint64
    Data   []byte
    dirty  bool
}

func (p *Page) MarkDirty() {
    p.dirty = true
}

Why not immediately write every changed byte to disk? Because one reason to have a page cache is to let several logical changes happen in memory and write the page later. If record 1 and record 2 are on the same page, both changes can modify one cached 4096-byte buffer.

Dirty does not mean corruptA dirty page is simply a cached page whose memory contents are newer than the persisted file contents. “Dirty” is standard storage terminology for “needs writing before we can safely discard this buffer.”

7. Open the pager and validate page alignment

The pager owns the file handle. From this point onward, the store should eventually stop holding *os.File directly.

TYPE 3Define Pager state

type Pager struct {
    file     *os.File
    pages    map[uint64]*Page
    numPages uint64
}

The map is our first page cache: page number → in-memory page. It is intentionally simple and has no size limit yet.

TYPE 4Open the file as a sequence of complete pages

Add fmt and os imports, then add:

func OpenPager(path string) (*Pager, error) {
    file, err := os.OpenFile(path, os.O_RDWR|os.O_CREATE, 0644)
    if err != nil {
        return nil, err
    }

    info, err := file.Stat()
    if err != nil {
        file.Close()
        return nil, err
    }

    if info.Size()%PageSize != 0 {
        file.Close()
        return nil, fmt.Errorf("database size %d is not a multiple of page size %d",
            info.Size(), PageSize)
    }

    return &Pager{
        file:     file,
        pages:    make(map[uint64]*Page),
        numPages: uint64(info.Size() / PageSize),
    }, nil
}

This is a stronger invariant than Part 1 had. If a supposedly valid Part 2 file is 5000 bytes long, we refuse to guess what it means. It should contain whole pages.

The pager itself should be syntactically valid. Run gofmt -w pager.go frequently; it catches structure mistakes early.

8. GetPage has exactly three jobs

GetPage(pageNum) is the heart of this chapter. When a caller asks for a page, only three situations exist.

SituationMeaningAction
Page is already in pagesCache hitReturn the existing memory buffer. No file read.
pageNum < numPagesExisting page, not cachedAllocate 4096 bytes and read that page from disk.
pageNum == numPagesExactly the next pageCreate a new zero-filled page and extend the logical page count.

If pageNum > numPages, we reject the request. Why? Otherwise a bug could ask for page 900 in a three-page file and silently create a giant hole. Our current allocator only grows the file one page at a time.

TYPE 5First, the cache-hit branch

func (p *Pager) GetPage(pageNum uint64) (*Page, error) {
    if page, ok := p.pages[pageNum]; ok {
        return page, nil
    }

    // More cases come next.
    return nil, nil
}

That tiny branch is the reason future repeated reads can avoid repeated database-level file I/O.

TYPE 6Reject impossible gaps, then allocate the buffer

if pageNum > p.numPages {
    return nil, fmt.Errorf("cannot create page %d before page %d", pageNum, p.numPages)
}

page := &Page{
    Number: pageNum,
    Data:   make([]byte, PageSize),
}

make([]byte, PageSize) gives us 4096 zero bytes. For an existing page those zeros will immediately be replaced by bytes from the file. For a new page, zero is exactly the initial content we want.

TYPE 7Read an old page or create the next page

if pageNum < p.numPages {
    n, err := p.file.ReadAt(page.Data, int64(pageNum)*PageSize)
    if err != nil {
        return nil, fmt.Errorf("read page %d: %w", pageNum, err)
    }
    if n != PageSize {
        return nil, fmt.Errorf("read page %d: expected %d bytes, got %d",
            pageNum, PageSize, n)
    }
} else {
    // pageNum == numPages: append one new logical page.
    p.numPages++
}

p.pages[pageNum] = page
return page, nil

Study the read offset: int64(pageNum) * PageSize. This is the only place in the normal read path where page number becomes a physical byte position.

The abstraction boundary has appearedA caller says GetPage(2). The pager decides whether page 2 comes from RAM, from disk, or from a newly allocated zero buffer. The caller does not care which happened.

9. Dirty pages: changing RAM is not the same as persisting data

If a caller modifies page.Data, the file does not change automatically. The page is merely a slice in process memory. We therefore mark changed pages dirty and teach the pager how to flush them.

TYPE 8Flush one page

func (p *Pager) FlushPage(pageNum uint64) error {
    page, ok := p.pages[pageNum]
    if !ok || !page.dirty {
        return nil
    }

    n, err := p.file.WriteAt(page.Data, int64(pageNum)*PageSize)
    if err != nil {
        return fmt.Errorf("write page %d: %w", pageNum, err)
    }
    if n != PageSize {
        return fmt.Errorf("write page %d: expected %d bytes, wrote %d",
            pageNum, PageSize, n)
    }

    page.dirty = false
    return nil
}

Notice the symmetry:

read page N → ReadAt(buffer, N × PageSize) write page N → WriteAt(buffer, N × PageSize)

After a successful full write, the cached page and the file agree again, so dirty=false.

TYPE 9Flush all pages and close safely

func (p *Pager) FlushAll() error {
    for pageNum := range p.pages {
        if err := p.FlushPage(pageNum); err != nil {
            return err
        }
    }
    return p.file.Sync()
}

func (p *Pager) Close() error {
    flushErr := p.FlushAll()
    closeErr := p.file.Close()
    if flushErr != nil {
        return flushErr
    }
    return closeErr
}

Sync asks the operating system to synchronize the file's current contents to stable storage. It is useful, but do not confuse this with transaction safety. We can still crash between writing two related pages. That problem will become one of our next motivations.

10. Page 0 becomes database metadata

Now we reconnect to Part 1. We still need magic bytes, a version, and record-format assumptions. The difference is that the header is no longer 128 bytes followed immediately by data. The header owns a complete page.

TYPE 10Write the Part 2 header

In store.go, add encoding/binary and write:

func writeHeader(page *Page, nextID int64) {
    clear(page.Data)
    copy(page.Data[0:8], []byte("MINIDB02"))
    binary.LittleEndian.PutUint32(page.Data[8:12], 2)
    binary.LittleEndian.PutUint32(page.Data[12:16], PageSize)
    binary.LittleEndian.PutUint32(page.Data[16:20], RecordSize)
    binary.LittleEndian.PutUint64(page.Data[24:32], uint64(nextID))
    page.MarkDirty()
}

clear(page.Data) makes the entire header deterministic before we place fields into it. The unused bytes remain reserved zeros.

TYPE 11Read and validate the header

func readHeader(page *Page) (int64, error) {
    if string(page.Data[0:8]) != "MINIDB02" {
        return 0, fmt.Errorf("not a Part 2 MiniDB file: bad magic bytes")
    }

    version := binary.LittleEndian.Uint32(page.Data[8:12])
    if version != 2 {
        return 0, fmt.Errorf("unsupported database version %d", version)
    }

    pageSize := binary.LittleEndian.Uint32(page.Data[12:16])
    if pageSize != PageSize {
        return 0, fmt.Errorf("file page size is %d, program expects %d", pageSize, PageSize)
    }

    recordSize := binary.LittleEndian.Uint32(page.Data[16:20])
    if recordSize != RecordSize {
        return 0, fmt.Errorf("file record size is %d, program expects %d", recordSize, RecordSize)
    }

    nextID := int64(binary.LittleEndian.Uint64(page.Data[24:32]))
    if nextID < 1 {
        return 0, fmt.Errorf("invalid next id %d", nextID)
    }

    return nextID, nil
}

Why store page size inside a format whose parser already assumes 4096-byte pages? Because validation turns a hidden assumption into an explicit contract. If a future implementation uses a different size, it can fail loudly instead of misinterpreting every later offset.

Part 1 files should fail hereThat is intentional. A Part 1 file begins with MINIDB01 and has a different layout. Compatibility should be implemented as an explicit migration tool, not by making the new reader guess.

11. Store stops owning the file

This is the architectural change we have been working toward. In Part 1:

type Store struct {
    file *os.File
}

In Part 2:

type Store struct {
    pager  *Pager
    nextID int64
}

The store understands records. The pager understands pages and file I/O.

TYPE 12Open a new or existing database through the pager

func Open(path string) (*Store, error) {
    pager, err := OpenPager(path)
    if err != nil {
        return nil, err
    }

    if pager.numPages == 0 {
        header, err := pager.GetPage(HeaderPage)
        if err != nil {
            pager.Close()
            return nil, err
        }
        writeHeader(header, 1)
        if err := pager.FlushPage(HeaderPage); err != nil {
            pager.Close()
            return nil, err
        }
        return &Store{pager: pager, nextID: 1}, nil
    }

    header, err := pager.GetPage(HeaderPage)
    if err != nil {
        pager.Close()
        return nil, err
    }

    nextID, err := readHeader(header)
    if err != nil {
        pager.Close()
        return nil, err
    }

    return &Store{pager: pager, nextID: nextID}, nil
}

Read that in English. If there are zero pages, create page 0, write the first header, and persist it. Otherwise, load page 0 through the exact same pager path and validate it.

TYPE 13Close and flush through the pager

func (s *Store) Close() error {
    return s.pager.Close()
}

func (s *Store) Flush() error {
    return s.pager.FlushAll()
}

At this point, Store no longer needs direct calls to ReadAt, WriteAt, Stat, or Sync. Those concerns have moved down one layer.

12. INSERT through a page

We can reuse the Part 1 record encoding almost unchanged. That is a sign that the abstraction boundary is doing useful work. The binary format inside one record is separate from the way pages are loaded.

Keep the same 256-byte record fields:

0..7 ID (8 bytes) 8 deleted flag (1 byte) 9..40 name (32 bytes) 41..104 email (64 bytes) 105..108 age (4 bytes) 109..255 reserved/padding

Bring over your Part 1 User, encodeUser, and decodeUser functions. Do not change their job. They convert between a Go value and exactly 256 bytes.

TYPE 14Persist the logical next ID in page 0

func (s *Store) persistNextID() error {
    header, err := s.pager.GetPage(HeaderPage)
    if err != nil {
        return err
    }
    binary.LittleEndian.PutUint64(header.Data[24:32], uint64(s.nextID))
    header.MarkDirty()
    return nil
}

This call often becomes a cache hit because page 0 was already loaded when the database opened. That is exactly the behavior we want: metadata can be accessed by page number without forcing another file read.

TYPE 15Insert into a slot inside a page

func (s *Store) Insert(name, email string, age int32) (int64, error) {
    id := s.nextID
    pageNum, offset, err := recordLocation(id)
    if err != nil {
        return 0, err
    }

    record, err := encodeUser(User{ID: id, Name: name, Email: email, Age: age})
    if err != nil {
        return 0, err
    }

    page, err := s.pager.GetPage(pageNum)
    if err != nil {
        return 0, err
    }

    copy(page.Data[offset:offset+RecordSize], record)
    page.MarkDirty()

    s.nextID++
    if err := s.persistNextID(); err != nil {
        s.nextID--
        return 0, err
    }

    return id, nil
}

Walk through ID 17. recordLocation(17) returns page 2, offset 0. GetPage(2) sees that page 2 is exactly the next page after page 1, so it creates a new zero-filled 4096-byte buffer. We copy the 256-byte record into its first slot and mark page 2 dirty.

One insert no longer means one disk writeUntil we explicitly flush or close, an insert may change only cached memory: one data page and page 0's nextID. This is faster conceptually, but it creates a new responsibility: dirty pages must eventually be persisted correctly.

13. GET reads a record from a page buffer

Part 1's Get calculated a full file offset and read 256 bytes from the file. Part 2 calculates a page and an offset inside that page.

TYPE 16Get the page, then slice the record

func (s *Store) Get(id int64) (User, error) {
    if id < 1 || id >= s.nextID {
        return User{}, ErrNotFound
    }

    pageNum, offset, err := recordLocation(id)
    if err != nil {
        return User{}, err
    }

    page, err := s.pager.GetPage(pageNum)
    if err != nil {
        return User{}, err
    }

    u, err := decodeUser(page.Data[offset : offset+RecordSize])
    if err != nil {
        return User{}, err
    }
    if u.Deleted {
        return User{}, ErrDeleted
    }
    if u.ID != id {
        return User{}, fmt.Errorf("record %d is corrupt: stored id is %d", id, u.ID)
    }
    return u, nil
}

The important line is not the decoding. It is:

page, err := s.pager.GetPage(pageNum)

That line means Get has stopped caring whether the bytes are already in memory. If record 1 and record 2 live on page 1, asking for record 2 after record 1 reuses the same cached page.

14. SCAN is still linear—but its I/O story changes

Pages do not magically make SCAN asymptotically faster. We still visit every logical ID. There is no index yet.

func (s *Store) Scan() ([]User, error) {
    users := make([]User, 0, s.nextID-1)
    for id := int64(1); id < s.nextID; id++ {
        u, err := s.Get(id)
        if errors.Is(err, ErrDeleted) {
            continue
        }
        if err != nil {
            return nil, err
        }
        users = append(users, u)
    }
    return users, nil
}

But consider scanning IDs 1 through 16. The first call to Get(1) may load page 1 from disk. Get(2) through Get(16) ask for the same page number. They become cache hits.

That is a subtle but important distinction:

algorithmic work: still O(number of records) database page reads: approximately O(number of pages not already cached)

An index will later reduce the number of records/pages we need to visit for selective lookups. The pager gives that future index a standard way to obtain nodes from disk.

TYPE 17Add simple pager counters so we can observe behavior

Do not trust intuition when we can instrument the code. Add counters to Pager:

cacheHits  uint64
diskReads  uint64
diskWrites uint64

Increment cacheHits in the cache-hit branch, diskReads after a successful page read, and diskWrites after a successful dirty-page flush. Then expose:

type PagerStats struct {
    CachedPages int
    TotalPages  uint64
    CacheHits   uint64
    DiskReads   uint64
    DiskWrites  uint64
}

func (p *Pager) Stats() PagerStats {
    return PagerStats{
        CachedPages: len(p.pages),
        TotalPages:  p.numPages,
        CacheHits:   p.cacheHits,
        DiskReads:   p.diskReads,
        DiskWrites:  p.diskWrites,
    }
}

The counters are educational instrumentation, not production performance telemetry. They count calls made by our pager, while the operating system may perform its own caching underneath us.

15. DELETE becomes “modify one cached page”

Our tombstone design still works. The deleted flag is byte 8 inside a record. The difference is that the record itself is now a slice within a page.

TYPE 18Find the page and flip one byte

func (s *Store) Delete(id int64) error {
    if _, err := s.Get(id); err != nil {
        return err
    }

    pageNum, offset, err := recordLocation(id)
    if err != nil {
        return err
    }
    page, err := s.pager.GetPage(pageNum)
    if err != nil {
        return err
    }

    page.Data[offset+8] = 1
    page.MarkDirty()
    return nil
}

The +8 comes from the record layout, not the page layout. That distinction matters. Page math gets us to the record slot; record-format math gets us to the deleted byte inside the slot.

Trace ID 17ID 17 maps to page 2, slot offset 0. Its tombstone is therefore page 2 byte 8. At the file level that byte is 2×4096 + 8 = 8200. Notice that Delete itself never needs to compute 8200. The pager owns the page-to-file translation.

    fmt.Println("dirty pages flushed")

STATS lets us distinguish logical requests from actual pager reads. FLUSH lets us make the dirty→clean transition visible before process exit.

Now prove the cache is doing something

Reason about the expected shape before looking at exact numbers.

  • Opening the database loads page 0, so the pager starts with one cached page and one disk read.
  • GET 1 needs page 1, causing another disk read.
  • GET 2 also lives on page 1, so it should increase cache hits without increasing disk reads.
  • GET 17 lives on page 2, so disk reads increase again.

With the implementation at the end of this chapter, a clean reopened 20-record database produces this progression:

pages=3 cached=1 cache_hits=0 disk_reads=1 disk_writes=0

GET 1

GET 2
pages=3 cached=2 cache_hits=1 disk_reads=2 disk_writes=0

GET 17
pages=3 cached=3 cache_hits=1 disk_reads=3 disk_writes=0

That is the page cache in one experiment. Two logical record reads—IDs 1 and 2—share one physical database-page read.

18. What pages solve—and what they absolutely do not solve

It is easy to finish a chapter about a new abstraction and accidentally believe that abstraction solved more than it did. Let's be precise.

ProblemPart 2 statusWhy
Scattered raw file I/OMuch betterThe pager owns page reads, writes, file offsets, flushing, and the file handle.
Repeated reads of the same areaImprovedA loaded page is reused from the in-process cache.
Knowing what changedImprovedDirty state is tracked per page.
Unlimited memory useNot solvedOur map never evicts pages. A real buffer pool needs a capacity and replacement policy.
Slow selective lookupNot solvedWe still have no B-tree or other index.
Wasted fixed-record spaceNot solvedRecords are still 256 bytes with fixed name/email regions.
Reusing deleted slotsNot solvedTombstones remain holes; there is no free list.
Crash consistencyNot solvedRelated dirty pages can be written at different moments.
Concurrent readers/writersNot solvedThere is still no locking or MVCC.

The cache is intentionally unbounded

Our pages map keeps every loaded page forever. If the database contains one million 4096-byte pages and a long-running process touches all of them, this design is absurd: roughly four gigabytes of raw page buffers could accumulate, before accounting for Go object overhead.

That is not a mistake we need to hide. It creates the next design question: if the cache can hold only N pages, which page should be evicted? And before evicting a dirty page, what must happen? The dirty flag we added today is exactly the state an eviction policy will later need.

A more dangerous problem: two dirty pages can disagree after a crash

An insert changes at least two logical things: the data page receives the new record, and header page 0 advances nextID. Those pages are separate 4096-byte writes.

Imagine this order:

  1. page 0 is written with nextID=18,
  2. the process or machine crashes before page 2 containing record 17 is written.

After restart, the header says ID 17 should exist, but its data may not. Reverse the write order and you can get the opposite problem: the record reaches disk but the header still says the next ID is 17.

fsync is not a transaction protocolSync can help ensure writes already issued become durable. It does not make a multi-page logical change atomic. To survive crashes correctly, a database needs a protocol such as journaling or a write-ahead log, with carefully defined ordering and recovery rules.

Why pages matter beyond caching

Pages are not merely a speed trick. They give later data structures stable addresses. A B-tree node can say “my left child is page 42” instead of storing a Go pointer that becomes meaningless after process exit. A free-list entry can refer to a page number. A recovery log can describe which page changed. A buffer manager can pin a page while an operation is using it.

This is why Part 2 is architectural. The immediate program is still tiny, but the vocabulary of the storage engine has changed from arbitrary file offsets to page identities.

pager.go

package main

import (
	"fmt"
	"os"
)

const PageSize = 4096

type Page struct {
	Number uint64
	Data   []byte
	dirty  bool
}

func (p *Page) MarkDirty() {
	p.dirty = true
}

type PagerStats struct {
	CachedPages int
	TotalPages  uint64
	CacheHits   uint64
	DiskReads   uint64
	DiskWrites  uint64
}

type Pager struct {
	file       *os.File
	pages      map[uint64]*Page
	numPages   uint64
	cacheHits  uint64
	diskReads  uint64
	diskWrites uint64
}

func OpenPager(path string) (*Pager, error) {
	file, err := os.OpenFile(path, os.O_RDWR|os.O_CREATE, 0644)
	if err != nil {
		return nil, err
	}

	info, err := file.Stat()
	if err != nil {
		file.Close()
		return nil, err
	}

	if info.Size()%PageSize != 0 {
		file.Close()
		return nil, fmt.Errorf("database size %d is not a multiple of page size %d", info.Size(), PageSize)
	}

	return &Pager{
		file:     file,
		pages:    make(map[uint64]*Page),
		numPages: uint64(info.Size() / PageSize),
	}, nil
}

func (p *Pager) GetPage(pageNum uint64) (*Page, error) {
	if page, ok := p.pages[pageNum]; ok {
		p.cacheHits++
		return page, nil
	}

	if pageNum > p.numPages {
		return nil, fmt.Errorf("cannot create page %d before page %d", pageNum, p.numPages)
	}

	page := &Page{
		Number: pageNum,
		Data:   make([]byte, PageSize),
	}

	if pageNum < p.numPages {
		n, err := p.file.ReadAt(page.Data, int64(pageNum)*PageSize)
		if err != nil {
			return nil, fmt.Errorf("read page %d: %w", pageNum, err)
		}
		if n != PageSize {
			return nil, fmt.Errorf("read page %d: expected %d bytes, got %d", pageNum, PageSize, n)
		}
		p.diskReads++
	} else {
		// pageNum == numPages means append one new zero-filled logical page.
		p.numPages++
	}

	p.pages[pageNum] = page
	return page, nil
}

func (p *Pager) FlushPage(pageNum uint64) error {
	page, ok := p.pages[pageNum]
	if !ok || !page.dirty {
		return nil
	}

	n, err := p.file.WriteAt(page.Data, int64(pageNum)*PageSize)
	if err != nil {
		return fmt.Errorf("write page %d: %w", pageNum, err)
	}
	if n != PageSize {
		return fmt.Errorf("write page %d: expected %d bytes, wrote %d", pageNum, PageSize, n)
	}

	page.dirty = false
	p.diskWrites++
	return nil
}

func (p *Pager) FlushAll() error {
	for pageNum := range p.pages {
		if err := p.FlushPage(pageNum); err != nil {
			return err
		}
	}
	return p.file.Sync()
}

func (p *Pager) Stats() PagerStats {
	return PagerStats{
		CachedPages: len(p.pages),
		TotalPages:  p.numPages,
		CacheHits:   p.cacheHits,
		DiskReads:   p.diskReads,
		DiskWrites:  p.diskWrites,
	}
}

func (p *Pager) Close() error {
	flushErr := p.FlushAll()
	closeErr := p.file.Close()
	if flushErr != nil {
		return flushErr
	}
	return closeErr
}

store.go

package main

import (
	"encoding/binary"
	"errors"
	"fmt"
	"strings"
)

const (
	HeaderPage    = uint64(0)
	FirstDataPage = uint64(1)
	RecordSize    = 256
	MaxNameLen    = 32
	MaxEmailLen   = 64
	SlotsPerPage  = PageSize / RecordSize
)

var (
	ErrNotFound = errors.New("record not found")
	ErrDeleted  = errors.New("record deleted")
)

type Store struct {
	pager  *Pager
	nextID int64
}

type User struct {
	ID      int64
	Deleted bool
	Name    string
	Email   string
	Age     int32
}

func writeHeader(page *Page, nextID int64) {
	clear(page.Data)
	copy(page.Data[0:8], []byte("MINIDB02"))
	binary.LittleEndian.PutUint32(page.Data[8:12], 2)
	binary.LittleEndian.PutUint32(page.Data[12:16], PageSize)
	binary.LittleEndian.PutUint32(page.Data[16:20], RecordSize)
	binary.LittleEndian.PutUint64(page.Data[24:32], uint64(nextID))
	page.MarkDirty()
}

func readHeader(page *Page) (int64, error) {
	if string(page.Data[0:8]) != "MINIDB02" {
		return 0, fmt.Errorf("not a Part 2 MiniDB file: bad magic bytes")
	}

	version := binary.LittleEndian.Uint32(page.Data[8:12])
	if version != 2 {
		return 0, fmt.Errorf("unsupported database version %d", version)
	}

	pageSize := binary.LittleEndian.Uint32(page.Data[12:16])
	if pageSize != PageSize {
		return 0, fmt.Errorf("file page size is %d, program expects %d", pageSize, PageSize)
	}

	recordSize := binary.LittleEndian.Uint32(page.Data[16:20])
	if recordSize != RecordSize {
		return 0, fmt.Errorf("file record size is %d, program expects %d", recordSize, RecordSize)
	}

	nextID := int64(binary.LittleEndian.Uint64(page.Data[24:32]))
	if nextID < 1 {
		return 0, fmt.Errorf("invalid next id %d", nextID)
	}

	return nextID, nil
}

func Open(path string) (*Store, error) {
	pager, err := OpenPager(path)
	if err != nil {
		return nil, err
	}

	if pager.numPages == 0 {
		header, err := pager.GetPage(HeaderPage)
		if err != nil {
			pager.Close()
			return nil, err
		}
		writeHeader(header, 1)
		if err := pager.FlushPage(HeaderPage); err != nil {
			pager.Close()
			return nil, err
		}
		return &Store{pager: pager, nextID: 1}, nil
	}

	header, err := pager.GetPage(HeaderPage)
	if err != nil {
		pager.Close()
		return nil, err
	}

	nextID, err := readHeader(header)
	if err != nil {
		pager.Close()
		return nil, err
	}

	return &Store{pager: pager, nextID: nextID}, nil
}

func (s *Store) Close() error {
	return s.pager.Close()
}

func (s *Store) Flush() error {
	return s.pager.FlushAll()
}

func (s *Store) Stats() PagerStats {
	return s.pager.Stats()
}

func recordLocation(id int64) (uint64, int, error) {
	if id < 1 {
		return 0, 0, ErrNotFound
	}

	zeroBased := uint64(id - 1)
	pageNum := FirstDataPage + zeroBased/uint64(SlotsPerPage)
	slot := zeroBased % uint64(SlotsPerPage)
	offset := int(slot) * RecordSize
	return pageNum, offset, nil
}

func encodeUser(u User) ([]byte, error) {
	if len([]byte(u.Name)) > MaxNameLen {
		return nil, fmt.Errorf("name is longer than %d bytes", MaxNameLen)
	}
	if len([]byte(u.Email)) > MaxEmailLen {
		return nil, fmt.Errorf("email is longer than %d bytes", MaxEmailLen)
	}

	record := make([]byte, RecordSize)
	binary.LittleEndian.PutUint64(record[0:8], uint64(u.ID))
	if u.Deleted {
		record[8] = 1
	}
	copy(record[9:41], []byte(u.Name))
	copy(record[41:105], []byte(u.Email))
	binary.LittleEndian.PutUint32(record[105:109], uint32(u.Age))
	return record, nil
}

func decodeUser(record []byte) (User, error) {
	if len(record) != RecordSize {
		return User{}, fmt.Errorf("expected %d bytes, got %d", RecordSize, len(record))
	}

	return User{
		ID:      int64(binary.LittleEndian.Uint64(record[0:8])),
		Deleted: record[8] == 1,
		Name:    strings.TrimRight(string(record[9:41]), "\x00"),
		Email:   strings.TrimRight(string(record[41:105]), "\x00"),
		Age:     int32(binary.LittleEndian.Uint32(record[105:109])),
	}, nil
}

func (s *Store) persistNextID() error {
	header, err := s.pager.GetPage(HeaderPage)
	if err != nil {
		return err
	}
	binary.LittleEndian.PutUint64(header.Data[24:32], uint64(s.nextID))
	header.MarkDirty()
	return nil
}

func (s *Store) Insert(name, email string, age int32) (int64, error) {
	id := s.nextID
	pageNum, offset, err := recordLocation(id)
	if err != nil {
		return 0, err
	}

	record, err := encodeUser(User{ID: id, Name: name, Email: email, Age: age})
	if err != nil {
		return 0, err
	}

	page, err := s.pager.GetPage(pageNum)
	if err != nil {
		return 0, err
	}

	copy(page.Data[offset:offset+RecordSize], record)
	page.MarkDirty()

	s.nextID++
	if err := s.persistNextID(); err != nil {
		s.nextID--
		return 0, err
	}

	return id, nil
}

func (s *Store) Get(id int64) (User, error) {
	if id < 1 || id >= s.nextID {
		return User{}, ErrNotFound
	}

	pageNum, offset, err := recordLocation(id)
	if err != nil {
		return User{}, err
	}

	page, err := s.pager.GetPage(pageNum)
	if err != nil {
		return User{}, err
	}

	u, err := decodeUser(page.Data[offset : offset+RecordSize])
	if err != nil {
		return User{}, err
	}
	if u.Deleted {
		return User{}, ErrDeleted
	}
	if u.ID != id {
		return User{}, fmt.Errorf("record %d is corrupt: stored id is %d", id, u.ID)
	}
	return u, nil
}

func (s *Store) Scan() ([]User, error) {
	users := make([]User, 0, s.nextID-1)
	for id := int64(1); id < s.nextID; id++ {
		u, err := s.Get(id)
		if errors.Is(err, ErrDeleted) {
			continue
		}
		if err != nil {
			return nil, err
		}
		users = append(users, u)
	}
	return users, nil
}

func (s *Store) Delete(id int64) error {
	if _, err := s.Get(id); err != nil {
		return err
	}

	pageNum, offset, err := recordLocation(id)
	if err != nil {
		return err
	}
	page, err := s.pager.GetPage(pageNum)
	if err != nil {
		return err
	}

	page.Data[offset+8] = 1
	page.MarkDirty()
	return nil
}

import (
	"bufio"
	"fmt"
	"os"

	"strings"
)

func printUser(u User) {
	fmt.Printf("id=%d name=%s email=%s age=%d\n", u.ID, u.Name, u.Email, u.Age)
}

func main() {
	if len(os.Args) != 2 {
		fmt.Println("usage: minidb <database-file>")
		os.Exit(1)
	}

	store, err := Open(os.Args[1])

		fmt.Println("open error:", err)

		fmt.Print("minidb> ")

		}

		if len(parts) == 0 {
			continue
		}

		switch strings.ToUpper(parts[0]) {
		case "INSERT":

			if err != nil {

		case "GET":

				continue

				fmt.Println("id must be an integer")
				continue

			if err != nil {

			if err != nil {

				continue
			}
			for _, u := range users {

			}

			if len(parts) != 2 {
				fmt.Println("usage: DELETE <id>")
				continue
			}

				fmt.Println("id must be an integer")
				continue
			}

				fmt.Println("delete error:", err)
				continue
			}

			fmt.Printf("pages=%d cached=%d cache_hits=%d disk_reads=%d disk_writes=%d\n",
				st.TotalPages, st.CachedPages, st.CacheHits, st.DiskReads, st.DiskWrites)

		case "FLUSH":
			if err := store.Flush(); err != nil {
				fmt.Println("flush error:", err)
				continue
			}
			fmt.Println("dirty pages flushed")

		case "HELP":
			fmt.Println("INSERT <name> <email> <age>")
			fmt.Println("GET <id>")
			fmt.Println("SCAN")
			fmt.Println("DELETE <id>")
			fmt.Println("STATS")
			fmt.Println("FLUSH")
			fmt.Println("EXIT")

		case "EXIT", "QUIT":
			return

		default:
			fmt.Println("unknown command; try HELP")
		}
	}

	if err := scanner.Err(); err != nil {
		fmt.Println("input error:", err)
	}
}

21. What you should understand before leaving Part 2

Do not measure success by whether you can reproduce Pager.GetPage from memory. Measure it by whether you can narrate one request.

Suppose the process starts with a 20-record database and then executes GET 17. Opening the database asks the pager for page 0. Because page 0 is not cached and already exists in the file, the pager reads 4096 bytes starting at file offset 0. The store validates the header and learns nextID=21.

For ID 17, the store computes zeroBased=16, therefore page 2, slot 0, offset 0 within the page. It asks the pager for page 2. If page 2 is not cached, the pager reads 4096 bytes from file offset 2×4096=8192 and caches that buffer. The store takes bytes 0..255 from the buffer and gives them to decodeUser. The decoder interprets the ID, tombstone, name, email, and age.

If the next command is GET 18, the store computes page 2 again, now slot 1 at offset 256. The pager finds page 2 in its map and returns the existing buffer. No new pager-level disk read is necessary. The store decodes bytes 256..511.

If DELETE 18 follows, the store changes the tombstone byte inside that same cached page and marks the page dirty. The file still contains the previous bytes until FLUSH or Close writes the full page back at offset 8192.

If that story feels natural, Part 2 worked.You now have a storage boundary: higher layers ask for pages; the pager decides how those pages reach memory and how modified pages return to disk.

The pain that should now bother you

We gained a page cache, but it has no capacity limit. We can accumulate dirty pages, but a crash can happen while related pages are only partially persisted. We can refer to data by stable page numbers, but we still linearly scan records because there is no index. Those are not random missing features. They are the pressures that will drive the next storage-engine mechanisms.

Most importantly, pages should no longer sound like a database vocabulary word you memorized. You should be able to explain why they appeared: raw file access became too low-level and too scattered, so we introduced a fixed-size unit that one pager can load, cache, modify, and flush.

Part 2 complete

You started with raw byte offsets. You ended with page identities, a cache, dirty tracking, and one I/O boundary for the storage engine.
