Reliable File Format

Part 2 gave us pages and a pager. But the pager still trusts every 4096 bytes it reads. If a byte changes, if the wrong page lands at the wrong offset, or if the machine loses power halfway through a page write, our program may quietly interpret damaged bytes as valid database state. In Part 3 we stop trusting the file. Every page will carry enough structure to identify itself and enough redundancy to detect many forms of corruption.

How to use this chapterKeep Part 2 beside you, but build Part 3 in a copy. Do not paste the complete program from the end first. We will first break the Part 2 assumptions, then design the format on paper, then add page headers, checksums, metadata validation, verification tools, and corruption experiments one piece at a time. At each checkpoint, compile or run something observable. The aim is to make “reliable file format” concrete—not a list of database buzzwords.

1. Project setup: preserve Part 2 before changing the format

Part 3 changes the bytes on disk again. A Part 2 file begins each page directly with database payload. A Part 3 file begins every page with a common 32-byte page header. That means a Part 2 database is intentionally incompatible with Part 3.

That incompatibility is not a mistake. A file format is a contract. When the contract changes, silently pretending old bytes satisfy the new rules is more dangerous than rejecting them.

2. What is still unsafe after pages?

Part 2 improved organization, not trustworthiness. The pager can read page 7 and cache it, but once ReadAt returns 4096 bytes the program assumes those bytes are correct.

Imagine three failures.

One byte changes

A storage error, accidental edit, buggy program, or test tool changes one byte in a user's email. Part 2 has no page-wide integrity check. The record may still decode and look merely strange.

A valid page is misplaced

Suppose the 4096 bytes from page 1 are accidentally copied over page 2. Those bytes are perfectly readable and may contain valid-looking users. Part 2 cannot tell that they belong somewhere else.

A page write is torn

We intend to replace all 4096 bytes, but after a crash some portion comes from the new page and some from the old page. The OS call was conceptually “write a page”; durable storage may have experienced smaller writes underneath.

Metadata lies

Page 0 says nextID=101, but perhaps the last data-page update never became durable. Both pieces can be individually readable yet disagree semantically.

Didn't file.Sync() solve this?Sync asks the operating system to push pending changes toward durable storage. It matters for durability, but it is not a file-format validation mechanism. It does not let a future reader look at arbitrary bytes and answer “is this page internally intact and is it the page I expected?” We need information inside the file for that.

3. Reliability vocabulary: four different promises

Before coding, separate ideas that are often blurred together. A system can provide one without providing all of the others.

PropertyQuestionPart 3 status
Structural validityDo these bytes obey our declared format?We will improve this with magic bytes, versions, page types, page numbers, and metadata checks.
Integrity detectionCan we notice that bytes changed unexpectedly?We will add a checksum to every page.
DurabilityAfter we report success, are the intended changes persistent?We continue using full-page writes plus Sync, but real durability depends on the whole I/O stack.
Atomicity / recoveryIf a crash happens halfway through a multi-page operation, can we restore one coherent state?Not solved in Part 3. That requires journaling, WAL, copy-on-write, or another recovery protocol.

This distinction is the center of the chapter. A checksum is valuable because it converts some silent corruption into a loud error. It does not automatically reconstruct the missing bytes. Detection and recovery are different mechanisms.

Reliable does not mean impossible to corruptOur Part 3 goal is modest and precise: reject pages that fail our structural or checksum rules instead of blindly interpreting them. A production database needs stronger recovery, redundancy, careful write ordering, concurrency control, and extensive testing.

4. See the Part 2 weakness before fixing it

If you still have a Part 2 executable and database, this experiment is worth doing there. Insert a user, flush, exit, and use xxd to inspect the file. Then change one byte in a record with dd. Depending on which byte you change, Part 2 may happily print a damaged name or email because the page has no checksum.

That observation should motivate the new invariant:

New read ruleNo page from disk is trusted merely because 4096 bytes were returned. Before the pager exposes a persisted page to the store, the pager must validate the page header and checksum.

We keep PageSize = 4096. But every page now spends its first 32 bytes on a common page header. The rest is payload owned by the page's type.

4..5page-header versionLets the physical page-header scheme evolve independently of higher-level database metadata.

28..31reservedSpace for future physical-page metadata.

The checksum covers the entire 4096-byte page, including the header, except that the checksum field itself is treated as zero while calculating. This means changing a record, the page type, the generation, or the embedded page number changes the checksum.

The cost: we lose one record slot per page

In Part 2, all 4096 bytes were available to the record layer:

4096 / 256 = 16 records

In Part 3, only 4064 bytes remain after the 32-byte page header:

usable = 4096 - 32 = 4064 bytes slots = floor(4064 / 256) = 15 used by records = 15 × 256 = 3840 bytes unused tail = 4064 - 3840 = 224 bytes

We deliberately accept this inefficiency. Reliability metadata consumes space. Real storage engines make similar tradeoffs, though their page layouts are much more sophisticated.

6. Build the common page header

Open format.go. We will start with declarations only. This checkpoint should compile even though the rest of the program does not use the new format yet.

TYPE 1Declare the physical-page contract

package main

import "fmt"

const (
    PageSize          = 4096
    PageHeaderSize    = 32
    PageMagic         = "PG03"
    PageHeaderVersion = uint16(1)
    ChecksumAlgorithm = uint32(1) // CRC-32/IEEE
)

type PageType uint8

const (
    PageTypeMetadata PageType = 1
    PageTypeData     PageType = 2
)

func (t PageType) String() string {
    switch t {
    case PageTypeMetadata:
        return "metadata"
    case PageTypeData:
        return "data"
    default:
        return fmt.Sprintf("unknown(%d)", uint8(t))
    }
}
CheckpointRun gofmt -w *.go and go build .. If your old pager.go still declares PageSize, remove that duplicate declaration there. We are moving ownership of the physical format into format.go.

TYPE 2Initialize a brand-new page deliberately

A new page should not be “4096 mysterious zeroes.” As soon as it exists logically, give it identity.

func initializePageData(data []byte, pageNum uint64, pageType PageType) error {
    if len(data) != PageSize {
        return fmt.Errorf("initialize page: expected %d bytes, got %d", PageSize, len(data))
    }

    clear(data)
    copy(data[0:4], []byte(PageMagic))
    binary.LittleEndian.PutUint16(data[4:6], PageHeaderVersion)
    data[6] = byte(pageType)
    data[7] = 0
    binary.LittleEndian.PutUint64(data[8:16], pageNum)
    binary.LittleEndian.PutUint64(data[16:24], 0)
    binary.LittleEndian.PutUint32(data[24:28], 0)
    binary.LittleEndian.PutUint32(data[28:32], 0)
    return nil
}

Add encoding/binary to the imports. Notice that we still leave the checksum at zero. The page is not yet sealed for disk. It may receive metadata or records first.

Why embed the page number?Imagine copying an intact page 1 over page 2. A checksum over page 1 would still be valid, because the copied bytes are unchanged. But when the pager reads physical position 2, the embedded page number says “I am page 1.” That catches a class of corruption a checksum alone cannot distinguish.

7. Derive the checksum rule before calling a library

A checksum is a compact value computed from larger data. Change the data and the checksum will usually change. On read, we compute it again and compare.

MiniSQLite uses Go's standard hash/crc32 package with the IEEE polynomial. CRC-32 is useful for teaching accidental-corruption detection. It is not cryptographic authentication. Someone deliberately modifying a file can recompute CRC-32, and collisions are possible.

The self-reference problem

If the checksum is stored inside the page, should the checksum calculation include the checksum itself? That would be awkwardly self-referential. We define a precise rule instead:

checksum(page) = CRC32( bytes 0..23 + four zero bytes + bytes 28..4095 )

The persisted checksum lives at bytes 24..27, but those four bytes are treated as zero while calculating.

TYPE 3Compute without mutating the page

func computePageChecksum(data []byte) (uint32, error) {
    if len(data) != PageSize {
        return 0, fmt.Errorf("checksum: expected %d bytes, got %d", PageSize, len(data))
    }

    h := crc32.NewIEEE()
    _, _ = h.Write(data[:24])
    _, _ = h.Write([]byte{0, 0, 0, 0})
    _, _ = h.Write(data[28:])
    return h.Sum32(), nil
}

Add hash/crc32 to the imports.

TYPE 4Seal a page immediately before writing

“Sealing” means turning the current in-memory bytes into a self-describing persisted page: increment the generation, calculate the checksum, then store it.

func sealPageData(data []byte) (uint32, error) {
    generation := binary.LittleEndian.Uint64(data[16:24]) + 1
    binary.LittleEndian.PutUint64(data[16:24], generation)
    binary.LittleEndian.PutUint32(data[24:28], 0)

    checksum, err := computePageChecksum(data)
    if err != nil {
        return 0, err
    }
    binary.LittleEndian.PutUint32(data[24:28], checksum)
    return checksum, nil
}

Why seal during flush rather than every time a field changes? Because a cached page may receive several changes before it is written. The checksum should describe the exact bytes we are about to persist.

8. Validation is the inverse of sealing

On read, the program should prove several facts before handing the page to higher layers:

  1. The page is exactly 4096 bytes.
  2. The physical magic is PG03.
  3. The page-header version is supported.
  4. The page type is known.
  5. The embedded page number matches the file position requested.
  6. A nonzero checksum exists.
  7. The recomputed checksum equals the stored checksum.

TYPE 5Represent decoded header information

type PageHeaderInfo struct {
    Type       PageType
    Number     uint64
    Generation uint64
    Checksum   uint32
}

Then add a small decoder that reads those fields. The complete version is at the end; for now focus on the validation sequence.

TYPE 6Reject before interpreting payload

func validatePageData(expectedPageNum uint64, data []byte) (PageHeaderInfo, error) {
    if string(data[0:4]) != PageMagic {
        return PageHeaderInfo{}, fmt.Errorf("page %d: bad page magic", expectedPageNum)
    }

    info := decodePageHeader(data)
    if info.Number != expectedPageNum {
        return PageHeaderInfo{}, fmt.Errorf(
            "page %d: stored page number is %d", expectedPageNum, info.Number)
    }

    computed, err := computePageChecksum(data)
    if err != nil {
        return PageHeaderInfo{}, err
    }
    if computed != info.Checksum {
        return PageHeaderInfo{}, fmt.Errorf(
            "page %d: checksum mismatch: stored=%08x computed=%08x",
            expectedPageNum, info.Checksum, computed)
    }

    return info, nil
}
This snippet is intentionally incompleteThe final validator also checks length, header version, valid page type, and missing checksum. We are splitting it here so you can see the logical order instead of receiving a wall of defensive code.

9. Teach the pager to validate every persisted page

This is the architectural payoff. The store should not remember to verify checksums. Every caller that asks the pager for an existing page gets a validated page or an error.

TYPE 7Give Page an explicit type

Change the Part 2 page structure from:

type Page struct {
    Number uint64
    Data   []byte
    dirty  bool
}

to:

type Page struct {
    Number uint64
    Type   PageType
    Data   []byte
    dirty  bool
}

TYPE 8Make the caller state what type it expects

Change the pager API from GetPage(pageNum) to:

GetPage(pageNum uint64, expectedType PageType)

This gives us another invariant. Page 0 must be metadata. Record pages must be data pages. If bytes claim otherwise, stop.

Existing page path

After reading 4096 bytes, Part 2 immediately cached the page. Part 3 inserts validation first:

n, err := p.file.ReadAt(page.Data, int64(pageNum)*PageSize)
if err != nil && err != io.EOF {
    return nil, fmt.Errorf("read page %d: %w", pageNum, err)
}
if n != PageSize {
    return nil, fmt.Errorf("read page %d: expected %d bytes, got %d", pageNum, PageSize, n)
}

info, err := validatePageData(pageNum, page.Data)
if err != nil {
    p.validationFailures++
    return nil, err
}
if info.Type != expectedType {
    p.validationFailures++
    return nil, fmt.Errorf("page %d: expected type %s, got %s",
        pageNum, expectedType, info.Type)
}

page.Type = info.Type
p.pages[pageNum] = page

The key detail is ordering: read → validate → cache/expose. Never cache an unvalidated persisted page as if it were trusted state.

New page path

A brand-new logical page has no bytes on disk to validate yet. Initialize its page header, mark it dirty, and let the normal flush path seal it later:

if pageNum == p.numPages {
    if err := initializePageData(page.Data, pageNum, expectedType); err != nil {
        return nil, err
    }
    page.MarkDirty()
    p.numPages++
    p.pages[pageNum] = page
    return page, nil
}
CheckpointAt this point, switch all existing Part 2 calls temporarily to pass a page type: page 0 uses PageTypeMetadata; record pages use PageTypeData. Build. Do not worry yet that old Part 2 database files fail. That failure is expected because their pages do not contain PG03 headers.

10. Dirty pages must be sealed before they touch disk

Part 2 wrote page.Data directly. Part 3 must update generation and checksum immediately before the write.

TYPE 9Add one line to the flush path

if _, err := sealPageData(page.Data); err != nil {
    return err
}

Then keep the existing full-write check and only clear dirty after all 4096 bytes were accepted by WriteAt.

Why keep a generation if the checksum already detects changes?The generation is not required for CRC validation. It tells us which sealed revision of a page we are looking at and creates useful vocabulary for future recovery logic. But a generation stored only inside the same page cannot by itself prove that the page is the newest expected revision. If an old whole page survives with a valid checksum and old generation, we need some external recovery protocol to know it is stale.

11. Page 0 now has two layers of meaning

Page 0 is first a valid physical Part 3 page. Its first 32 bytes follow the same common header as every other page. Then its payload contains database metadata.

TYPE 10Write metadata inside the payload, not over the page header

func writeDatabaseMetadata(page *Page, nextID int64) {
    clear(page.Data[PageHeaderSize:])
    copy(page.Data[32:40], []byte("MINIDB03"))
    binary.LittleEndian.PutUint32(page.Data[40:44], 3)
    binary.LittleEndian.PutUint32(page.Data[44:48], PageSize)
    binary.LittleEndian.PutUint32(page.Data[48:52], RecordSize)
    binary.LittleEndian.PutUint32(page.Data[52:56], PageHeaderSize)
    binary.LittleEndian.PutUint32(page.Data[56:60], ChecksumAlgorithm)
    binary.LittleEndian.PutUint64(page.Data[64:72], uint64(nextID))
    page.MarkDirty()
}

Using named offsets, as the final program does, is better than leaving raw numbers everywhere. The snippet above exposes the byte layout visually first.

Why two versions?

The common page header has a page-header version. The database payload has a database version. These can evolve at different speeds. For example, a future database version might reorganize records while retaining the same physical checksum header. Separating layers keeps the format easier to reason about.

TYPE 11Change exactly one mapping function

const SlotsPerPage = (PageSize - PageHeaderSize) / RecordSize

func recordLocation(id int64) (uint64, int, error) {
    if id < 1 {
        return 0, 0, ErrNotFound
    }

    zeroBased := uint64(id - 1)
    pageNum := FirstDataPage + zeroBased/uint64(SlotsPerPage)
    slot := zeroBased % uint64(SlotsPerPage)
    offset := PageHeaderSize + int(slot)*RecordSize
    return pageNum, offset, nil
}
This is why centralized layout math mattersBecause Part 2 put record placement in one helper, Part 3 can change the physical record start and records-per-page without rewriting arithmetic in INSERT, GET, and DELETE independently.

13. Move Store to the Part 3 format one operation at a time

The record encoder itself does not change. A 256-byte user record is still ID, tombstone, name, email, age, and padding. What changes is the page contract surrounding it.

Opening a new database

When the file has zero pages:

  1. Ask for page 0 as PageTypeMetadata.
  2. The pager initializes its common page header and marks it dirty.
  3. The store writes database metadata into the payload.
  4. FlushAll seals the page, calculates the checksum, writes 4096 bytes, and syncs.
header, err := pager.GetPage(HeaderPage, PageTypeMetadata)
if err != nil {
    pager.Close()
    return nil, err
}
writeDatabaseMetadata(header, 1)
if err := pager.FlushAll(); err != nil {
    pager.Close()
    return nil, err
}

Opening an existing database

The order becomes layered validation:

pager
PG03 + page number + CRC
→
store
MINIDB03 + sizes + algorithm
→
usable DB
nextID accepted

If physical page validation fails, we never even try to interpret database metadata.

INSERT

The logic remains conceptually familiar, which is evidence that the pager abstraction is working:

page, err := s.pager.GetPage(pageNum, PageTypeData)
if err != nil {
    return 0, err
}

copy(page.Data[offset:offset+RecordSize], record)
page.MarkDirty()

The checksum is not recomputed here. The page is simply dirty. Flush owns sealing.

GET

GET asks for a data page. If the page is coming from disk for the first time, checksum validation happens before the record decoder sees one byte of its payload.

page, err := s.pager.GetPage(pageNum, PageTypeData)
if err != nil {
    return User{}, err
}

u, err := decodeUser(page.Data[offset : offset+RecordSize])

This means a checksum failure surfaces as a page error rather than a misleading “user has weird email” result.

DELETE

DELETE changes one tombstone byte and marks the containing page dirty. At flush time, the entire 4096-byte page receives a new generation and checksum.

14. Add tools that make reliability visible

Reliability code is easier to understand when the program can show its evidence. Part 3 adds two terminal commands.

PAGEINFO <n>

This prints the common header identity for a page after ensuring the page is sealed and valid:

minidb> PAGEINFO 0
page=0 type=metadata generation=2 checksum=6845da17
minidb> PAGEINFO 1
page=1 type=data generation=1 checksum=ec18d324

Your exact generations and checksums will differ. The important thing is that these are now persisted facts, not invisible implementation state.

VERIFY

GET only touches pages needed for that request. A database might contain a corrupt page you have not read yet. VERIFY provides an explicit full-file integrity pass:

  1. Flush dirty pages.
  2. Read every physical page directly from disk.
  3. Validate magic, header version, page type, embedded page number, and checksum.
  4. Validate database metadata on page 0.
minidb> VERIFY
verified 3 pages

TYPE 12The verification loop

func (p *Pager) VerifyAll() (uint64, error) {
    buf := make([]byte, PageSize)
    for pageNum := uint64(0); pageNum < p.numPages; pageNum++ {
        n, err := p.file.ReadAt(buf, int64(pageNum)*PageSize)
        if err != nil && err != io.EOF {
            return pageNum, err
        }
        if n != PageSize {
            return pageNum, fmt.Errorf("verify page %d: short read", pageNum)
        }
        if _, err := validatePageData(pageNum, buf); err != nil {
            return pageNum, err
        }
    }
    return p.numPages, nil
}

Notice that VERIFY reads persisted bytes, not merely cached objects. Its question is specifically: “Does the file on disk satisfy our Part 3 page invariants?”

15. Practical lab: corrupt one byte and watch detection happen

Create a clean database with 20 records. The easiest way is to use your normal CLI. Flush and exit. Then make a backup:

cp lesson.db lesson-good.db

ID 16 is the first record on page 2. Its record begins at:

physical page 2 offset = 2 × 4096 = 8192 record payload offset = 32 name field starts = record + 9 absolute name byte = 8192 + 32 + 9 = 8233

Change exactly one byte:

printf 'ÿ' | dd of=lesson.db bs=1 seek=8233 count=1 conv=notrunc

Now reopen:

./minidb lesson.db
minidb> GET 16
get error: page 2: checksum mismatch: stored=........ computed=........

The exact hex values are not important. What matters is what did not happen: MiniSQLite did not decode the damaged record and return a subtly corrupted user. The page was rejected at the storage boundary.

Silent corruption became explicit corruptionWe still lost trustworthy access to that page. Checksums did not repair it. But an explicit integrity error is dramatically safer than quietly passing damaged bytes upward.

16. Practical lab: a valid page in the wrong position

Restore the clean database first:

cp lesson-good.db misplaced.db

Now copy the entire valid page 1 over physical page 2:

dd if=lesson-good.db of=misplaced.db bs=4096 skip=1 seek=2 count=1 conv=notrunc

What is interesting here? The copied 4096 bytes still carry page 1's valid checksum. If our only rule were “CRC must match,” the bytes would look internally intact.

But physical position 2 expects an embedded page number of 2:

./minidb misplaced.db
minidb> GET 16
get error: page 2: stored page number is 1

This is why the page header stores identity in addition to integrity.

17. Torn writes: why a 4096-byte WriteAt is not a magic atomic unit

Our code asks the operating system to write 4096 bytes. That does not mean power loss can only produce “all old” or “all new.” Storage layers may operate in smaller units; caches, controllers, filesystems, and hardware all participate. A crash can leave a page containing a mixture.

Intended new page
new header + new checksum + new payload
Possible torn page after crash
new first portion + old remaining portion

If the persisted checksum came from the new page but part of the payload stayed old, recomputation should disagree. That is one important thing a page checksum can detect.

But there are two subtleties:

  • A CRC has a finite number of values, so accidental collisions are possible, though uncommon enough for this teaching purpose.
  • If the storage system leaves the entire old page intact, its old checksum is still valid. A page-local checksum cannot prove freshness by itself.

18. Practical lab: simulate a torn page

We can simulate a mixed old/new page without actually pulling the power cable.

Step A — create the “old” version

Create exactly 15 records, flush, exit, and copy the file:

cp lesson.db before-delete.db

ID 15 lives late in page 1: its record begins at offset 3616 inside the page, so its tombstone byte is beyond the halfway point.

Step B — create a “new” version

Open the database, delete ID 15, flush, exit:

./minidb lesson.db
minidb> DELETE 15
record 15 deleted
minidb> FLUSH
dirty pages sealed, checksummed, and flushed
minidb> EXIT
cp lesson.db after-delete.db

The new page 1 contains both a new checksum near the start and a changed tombstone late in the page.

Step C — splice half new and half old

Start from the old file:

cp before-delete.db torn.db

Copy only the first 2048 bytes of page 1 from the new file into the old file:

dd if=after-delete.db of=torn.db bs=1 skip=4096 seek=4096 count=2048 conv=notrunc

Now page 1 has the new header/checksum in its first half but the old second half, where ID 15's tombstone still says “not deleted.”

./minidb torn.db
minidb> VERIFY
verify error: page 1: checksum mismatch: stored=........ computed=........

You have created an artificial torn page and observed the detection mechanism directly.

19. What checksums and metadata still cannot guarantee

This section matters as much as the implementation. It prevents us from overclaiming what Part 3 achieved.

Case 1 — data page new, metadata page old

INSERT changes at least two logical pieces of state: a data page receives the record, and metadata page 0 advances nextID. Suppose the data page reaches durable storage but page 0 does not. Both pages can have valid checksums, yet the database may ignore a record that physically exists.

Case 2 — metadata page new, data page old

The reverse is worse: nextID may claim a new record exists while its data page still contains the previous bytes. Again, every page can be individually checksum-valid. The inconsistency is between pages.

Case 3 — an entire older page survives

An old page has a valid old generation and matching checksum. Without another durable record saying “page 7 must be at generation 42,” page 7 alone cannot prove that generation 41 is stale.

Case 4 — malicious modification

CRC-32 is not a cryptographic MAC. Anyone able to edit the database can edit bytes and recompute the CRC. Our threat model is accidental corruption detection, not tamper-proof storage.

The next conceptual pressurePart 3 gives pages integrity, identity, and format metadata. The remaining crash problem is multi-page consistency: how do several related page changes become one recoverable operation? Typical answers involve a rollback journal, write-ahead log (WAL), copy-on-write scheme, or another recovery protocol. Checksums complement those systems; they do not replace them.

Exercise 1 — byte-layout prediction

Exercise 2 — checksum avalanche experiment

Record PAGEINFO 1. Change one user on page 1, flush, and run PAGEINFO 1 again. Which fields change? Explain why the checksum changes even if only one record byte changed.

Exercise 3 — corrupt the checksum field itself

Exercise 4 — corrupt the page type

Change page 1's type byte from 2 to 1 without fixing the checksum. Observe the checksum failure. Then, as a thought experiment, suppose someone recomputed the checksum too. Which additional expected-type check would still reject the page?

Exercise 5 — duplicate a page

Exercise 7 — stale page thought experiment

format.go

package main

import (
	"encoding/binary"
	"fmt"
	"hash/crc32"
)

const (
	PageSize          = 4096
	PageHeaderSize    = 32
	PageMagic         = "PG03"
	PageHeaderVersion = uint16(1)
	ChecksumAlgorithm = uint32(1) // CRC-32/IEEE
)

type PageType uint8

const (
	PageTypeMetadata PageType = 1
	PageTypeData     PageType = 2
)

func (t PageType) String() string {
	switch t {
	case PageTypeMetadata:
		return "metadata"
	case PageTypeData:
		return "data"
	default:
		return fmt.Sprintf("unknown(%d)", uint8(t))
	}
}

type PageHeaderInfo struct {
	Type       PageType
	Number     uint64
	Generation uint64
	Checksum   uint32
}

func validPageType(t PageType) bool {
	return t == PageTypeMetadata || t == PageTypeData
}

func initializePageData(data []byte, pageNum uint64, pageType PageType) error {
	if len(data) != PageSize {
		return fmt.Errorf("initialize page: expected %d bytes, got %d", PageSize, len(data))
	}
	if !validPageType(pageType) {
		return fmt.Errorf("initialize page: invalid page type %d", pageType)
	}

	clear(data)
	copy(data[0:4], []byte(PageMagic))
	binary.LittleEndian.PutUint16(data[4:6], PageHeaderVersion)
	data[6] = byte(pageType)
	data[7] = 0 // flags; reserved for later
	binary.LittleEndian.PutUint64(data[8:16], pageNum)
	binary.LittleEndian.PutUint64(data[16:24], 0) // generation
	binary.LittleEndian.PutUint32(data[24:28], 0) // checksum is filled at flush
	binary.LittleEndian.PutUint32(data[28:32], 0) // reserved
	return nil
}

func computePageChecksum(data []byte) (uint32, error) {
	if len(data) != PageSize {
		return 0, fmt.Errorf("checksum: expected %d bytes, got %d", PageSize, len(data))
	}

	h := crc32.NewIEEE()
	_, _ = h.Write(data[:24])
	_, _ = h.Write([]byte{0, 0, 0, 0})
	_, _ = h.Write(data[28:])
	return h.Sum32(), nil
}

func sealPageData(data []byte) (PageHeaderInfo, error) {
	if len(data) != PageSize {
		return PageHeaderInfo{}, fmt.Errorf("seal page: expected %d bytes, got %d", PageSize, len(data))
	}

	generation := binary.LittleEndian.Uint64(data[16:24]) + 1
	binary.LittleEndian.PutUint64(data[16:24], generation)
	binary.LittleEndian.PutUint32(data[24:28], 0)

	checksum, err := computePageChecksum(data)
	if err != nil {
		return PageHeaderInfo{}, err
	}
	binary.LittleEndian.PutUint32(data[24:28], checksum)

	return decodePageHeader(data), nil
}

func decodePageHeader(data []byte) PageHeaderInfo {
	return PageHeaderInfo{
		Type:       PageType(data[6]),
		Number:     binary.LittleEndian.Uint64(data[8:16]),
		Generation: binary.LittleEndian.Uint64(data[16:24]),
		Checksum:   binary.LittleEndian.Uint32(data[24:28]),
	}
}

func validatePageData(expectedPageNum uint64, data []byte) (PageHeaderInfo, error) {
	if len(data) != PageSize {
		return PageHeaderInfo{}, fmt.Errorf("page %d: expected %d bytes, got %d", expectedPageNum, PageSize, len(data))
	}
	if string(data[0:4]) != PageMagic {
		return PageHeaderInfo{}, fmt.Errorf("page %d: bad page magic %q", expectedPageNum, string(data[0:4]))
	}

	headerVersion := binary.LittleEndian.Uint16(data[4:6])
	if headerVersion != PageHeaderVersion {
		return PageHeaderInfo{}, fmt.Errorf("page %d: unsupported page-header version %d", expectedPageNum, headerVersion)
	}

	info := decodePageHeader(data)
	if !validPageType(info.Type) {
		return PageHeaderInfo{}, fmt.Errorf("page %d: invalid page type %d", expectedPageNum, info.Type)
	}
	if info.Number != expectedPageNum {
		return PageHeaderInfo{}, fmt.Errorf("page %d: stored page number is %d", expectedPageNum, info.Number)
	}
	if info.Checksum == 0 {
		return PageHeaderInfo{}, fmt.Errorf("page %d: missing checksum", expectedPageNum)
	}

	computed, err := computePageChecksum(data)
	if err != nil {
		return PageHeaderInfo{}, err
	}
	if computed != info.Checksum {
		return PageHeaderInfo{}, fmt.Errorf("page %d: checksum mismatch: stored=%08x computed=%08x", expectedPageNum, info.Checksum, computed)
	}

	return info, nil
}

pager.go

package main

import (
	"fmt"
	"io"
	"os"
)

type Page struct {
	Number uint64
	Type   PageType
	Data   []byte
	dirty  bool
}

func (p *Page) MarkDirty() {
	p.dirty = true
}

type PagerStats struct {
	CachedPages        int
	TotalPages         uint64
	CacheHits          uint64
	DiskReads          uint64
	DiskWrites         uint64
	ValidationFailures uint64
}

type Pager struct {
	file               *os.File
	pages              map[uint64]*Page
	numPages           uint64
	cacheHits          uint64
	diskReads          uint64
	diskWrites         uint64
	validationFailures uint64
}

func OpenPager(path string) (*Pager, error) {
	file, err := os.OpenFile(path, os.O_RDWR|os.O_CREATE, 0644)
	if err != nil {
		return nil, err
	}

	info, err := file.Stat()
	if err != nil {
		file.Close()
		return nil, err
	}
	if info.Size()%PageSize != 0 {
		file.Close()
		return nil, fmt.Errorf("database size %d is not a multiple of page size %d", info.Size(), PageSize)
	}

	return &Pager{
		file:     file,
		pages:    make(map[uint64]*Page),
		numPages: uint64(info.Size() / PageSize),
	}, nil
}

func (p *Pager) GetPage(pageNum uint64, expectedType PageType) (*Page, error) {
	if page, ok := p.pages[pageNum]; ok {
		if page.Type != expectedType {
			return nil, fmt.Errorf("page %d: expected type %s, got %s", pageNum, expectedType, page.Type)
		}
		p.cacheHits++
		return page, nil
	}

	if pageNum > p.numPages {
		return nil, fmt.Errorf("cannot create page %d before page %d", pageNum, p.numPages)
	}

	page := &Page{
		Number: pageNum,
		Type:   expectedType,
		Data:   make([]byte, PageSize),
	}

	if pageNum == p.numPages {
		if err := initializePageData(page.Data, pageNum, expectedType); err != nil {
			return nil, err
		}
		page.MarkDirty()
		p.numPages++
		p.pages[pageNum] = page
		return page, nil
	}

	n, err := p.file.ReadAt(page.Data, int64(pageNum)*PageSize)
	if err != nil && err != io.EOF {
		return nil, fmt.Errorf("read page %d: %w", pageNum, err)
	}
	if n != PageSize {
		return nil, fmt.Errorf("read page %d: expected %d bytes, got %d", pageNum, PageSize, n)
	}
	p.diskReads++

	info, err := validatePageData(pageNum, page.Data)
	if err != nil {
		p.validationFailures++
		return nil, err
	}
	if info.Type != expectedType {
		p.validationFailures++
		return nil, fmt.Errorf("page %d: expected type %s, got %s", pageNum, expectedType, info.Type)
	}

	page.Type = info.Type
	p.pages[pageNum] = page
	return page, nil
}

func (p *Pager) FlushPage(pageNum uint64) error {
	page, ok := p.pages[pageNum]
	if !ok || !page.dirty {
		return nil
	}

	if _, err := sealPageData(page.Data); err != nil {
		return err
	}

	n, err := p.file.WriteAt(page.Data, int64(pageNum)*PageSize)
	if err != nil {
		return fmt.Errorf("write page %d: %w", pageNum, err)
	}
	if n != PageSize {
		return fmt.Errorf("write page %d: expected %d bytes, wrote %d", pageNum, PageSize, n)
	}

	page.dirty = false
	p.diskWrites++
	return nil
}

func (p *Pager) FlushAll() error {
	for pageNum := range p.pages {
		if err := p.FlushPage(pageNum); err != nil {
			return err
		}
	}
	return p.file.Sync()
}

func (p *Pager) VerifyAll() (uint64, error) {
	buf := make([]byte, PageSize)
	for pageNum := uint64(0); pageNum < p.numPages; pageNum++ {
		n, err := p.file.ReadAt(buf, int64(pageNum)*PageSize)
		if err != nil && err != io.EOF {
			return pageNum, fmt.Errorf("verify page %d: %w", pageNum, err)
		}
		if n != PageSize {
			p.validationFailures++
			return pageNum, fmt.Errorf("verify page %d: expected %d bytes, got %d", pageNum, PageSize, n)
		}
		if _, err := validatePageData(pageNum, buf); err != nil {
			p.validationFailures++
			return pageNum, err
		}
	}
	return p.numPages, nil
}

func (p *Pager) PageInfo(pageNum uint64, expectedType PageType) (PageHeaderInfo, error) {
	page, err := p.GetPage(pageNum, expectedType)
	if err != nil {
		return PageHeaderInfo{}, err
	}
	if page.dirty {
		if err := p.FlushPage(pageNum); err != nil {
			return PageHeaderInfo{}, err
		}
	}
	return validatePageData(pageNum, page.Data)
}

func (p *Pager) Stats() PagerStats {
	return PagerStats{
		CachedPages:        len(p.pages),
		TotalPages:         p.numPages,
		CacheHits:          p.cacheHits,
		DiskReads:          p.diskReads,
		DiskWrites:         p.diskWrites,
		ValidationFailures: p.validationFailures,
	}
}

func (p *Pager) Close() error {
	flushErr := p.FlushAll()
	closeErr := p.file.Close()
	if flushErr != nil {
		return flushErr
	}
	return closeErr
}

store.go

package main

import (
	"encoding/binary"
	"errors"
	"fmt"
	"strings"
)

const (
	DatabaseMagic   = "MINIDB03"
	DatabaseVersion = uint32(3)

	HeaderPage    = uint64(0)
	FirstDataPage = uint64(1)

	RecordSize   = 256
	MaxNameLen   = 32
	MaxEmailLen  = 64
	SlotsPerPage = (PageSize - PageHeaderSize) / RecordSize

	metaMagicOffset          = PageHeaderSize
	metaVersionOffset        = metaMagicOffset + 8
	metaPageSizeOffset       = metaVersionOffset + 4
	metaRecordSizeOffset     = metaPageSizeOffset + 4
	metaPageHeaderSizeOffset = metaRecordSizeOffset + 4
	metaChecksumAlgOffset    = metaPageHeaderSizeOffset + 4
	metaNextIDOffset         = 64
)

var (
	ErrNotFound = errors.New("record not found")
	ErrDeleted  = errors.New("record deleted")
)

type Store struct {
	pager  *Pager
	nextID int64
}

type User struct {
	ID      int64
	Deleted bool
	Name    string
	Email   string
	Age     int32
}

func writeDatabaseMetadata(page *Page, nextID int64) {
	clear(page.Data[PageHeaderSize:])
	copy(page.Data[metaMagicOffset:metaMagicOffset+8], []byte(DatabaseMagic))
	binary.LittleEndian.PutUint32(page.Data[metaVersionOffset:metaVersionOffset+4], DatabaseVersion)
	binary.LittleEndian.PutUint32(page.Data[metaPageSizeOffset:metaPageSizeOffset+4], PageSize)
	binary.LittleEndian.PutUint32(page.Data[metaRecordSizeOffset:metaRecordSizeOffset+4], RecordSize)
	binary.LittleEndian.PutUint32(page.Data[metaPageHeaderSizeOffset:metaPageHeaderSizeOffset+4], PageHeaderSize)
	binary.LittleEndian.PutUint32(page.Data[metaChecksumAlgOffset:metaChecksumAlgOffset+4], ChecksumAlgorithm)
	binary.LittleEndian.PutUint64(page.Data[metaNextIDOffset:metaNextIDOffset+8], uint64(nextID))
	page.MarkDirty()
}

func readDatabaseMetadata(page *Page) (int64, error) {
	if page.Type != PageTypeMetadata {
		return 0, fmt.Errorf("page 0 is %s, expected metadata", page.Type)
	}
	if string(page.Data[metaMagicOffset:metaMagicOffset+8]) != DatabaseMagic {
		return 0, fmt.Errorf("not a Part 3 MiniDB file: bad database magic")
	}

	version := binary.LittleEndian.Uint32(page.Data[metaVersionOffset : metaVersionOffset+4])
	if version != DatabaseVersion {
		return 0, fmt.Errorf("unsupported database version %d", version)
	}
	if got := binary.LittleEndian.Uint32(page.Data[metaPageSizeOffset : metaPageSizeOffset+4]); got != PageSize {
		return 0, fmt.Errorf("file page size is %d, program expects %d", got, PageSize)
	}
	if got := binary.LittleEndian.Uint32(page.Data[metaRecordSizeOffset : metaRecordSizeOffset+4]); got != RecordSize {
		return 0, fmt.Errorf("file record size is %d, program expects %d", got, RecordSize)
	}
	if got := binary.LittleEndian.Uint32(page.Data[metaPageHeaderSizeOffset : metaPageHeaderSizeOffset+4]); got != PageHeaderSize {
		return 0, fmt.Errorf("file page-header size is %d, program expects %d", got, PageHeaderSize)
	}
	if got := binary.LittleEndian.Uint32(page.Data[metaChecksumAlgOffset : metaChecksumAlgOffset+4]); got != ChecksumAlgorithm {
		return 0, fmt.Errorf("unsupported checksum algorithm %d", got)
	}

	nextID := int64(binary.LittleEndian.Uint64(page.Data[metaNextIDOffset : metaNextIDOffset+8]))
	if nextID < 1 {
		return 0, fmt.Errorf("invalid next id %d", nextID)
	}
	return nextID, nil
}

func Open(path string) (*Store, error) {
	pager, err := OpenPager(path)
	if err != nil {
		return nil, err
	}

	if pager.numPages == 0 {
		header, err := pager.GetPage(HeaderPage, PageTypeMetadata)
		if err != nil {
			pager.Close()
			return nil, err
		}
		writeDatabaseMetadata(header, 1)
		if err := pager.FlushAll(); err != nil {
			pager.Close()
			return nil, err
		}
		return &Store{pager: pager, nextID: 1}, nil
	}

	header, err := pager.GetPage(HeaderPage, PageTypeMetadata)
	if err != nil {
		pager.Close()
		return nil, err
	}
	nextID, err := readDatabaseMetadata(header)
	if err != nil {
		pager.Close()
		return nil, err
	}

	return &Store{pager: pager, nextID: nextID}, nil
}

func (s *Store) Close() error      { return s.pager.Close() }
func (s *Store) Flush() error      { return s.pager.FlushAll() }
func (s *Store) Stats() PagerStats { return s.pager.Stats() }

func (s *Store) Verify() (uint64, error) {
	if err := s.pager.FlushAll(); err != nil {
		return 0, err
	}
	pages, err := s.pager.VerifyAll()
	if err != nil {
		return 0, err
	}
	header, err := s.pager.GetPage(HeaderPage, PageTypeMetadata)
	if err != nil {
		return 0, err
	}
	if _, err := readDatabaseMetadata(header); err != nil {
		return 0, err
	}
	return pages, nil
}

func (s *Store) PageInfo(pageNum uint64) (PageHeaderInfo, error) {
	if pageNum >= s.pager.numPages {
		return PageHeaderInfo{}, fmt.Errorf("page %d does not exist", pageNum)
	}
	expected := PageTypeData
	if pageNum == HeaderPage {
		expected = PageTypeMetadata
	}
	return s.pager.PageInfo(pageNum, expected)
}

func recordLocation(id int64) (uint64, int, error) {
	if id < 1 {
		return 0, 0, ErrNotFound
	}
	zeroBased := uint64(id - 1)
	pageNum := FirstDataPage + zeroBased/uint64(SlotsPerPage)
	slot := zeroBased % uint64(SlotsPerPage)
	offset := PageHeaderSize + int(slot)*RecordSize
	return pageNum, offset, nil
}

func encodeUser(u User) ([]byte, error) {
	if len([]byte(u.Name)) > MaxNameLen {
		return nil, fmt.Errorf("name is longer than %d bytes", MaxNameLen)
	}
	if len([]byte(u.Email)) > MaxEmailLen {
		return nil, fmt.Errorf("email is longer than %d bytes", MaxEmailLen)
	}

	record := make([]byte, RecordSize)
	binary.LittleEndian.PutUint64(record[0:8], uint64(u.ID))
	if u.Deleted {
		record[8] = 1
	}
	copy(record[9:41], []byte(u.Name))
	copy(record[41:105], []byte(u.Email))
	binary.LittleEndian.PutUint32(record[105:109], uint32(u.Age))
	return record, nil
}

func decodeUser(record []byte) (User, error) {
	if len(record) != RecordSize {
		return User{}, fmt.Errorf("expected %d bytes, got %d", RecordSize, len(record))
	}
	return User{
		ID:      int64(binary.LittleEndian.Uint64(record[0:8])),
		Deleted: record[8] == 1,
		Name:    strings.TrimRight(string(record[9:41]), "\x00"),
		Email:   strings.TrimRight(string(record[41:105]), "\x00"),
		Age:     int32(binary.LittleEndian.Uint32(record[105:109])),
	}, nil
}

func (s *Store) persistNextID() error {
	header, err := s.pager.GetPage(HeaderPage, PageTypeMetadata)
	if err != nil {
		return err
	}
	binary.LittleEndian.PutUint64(header.Data[metaNextIDOffset:metaNextIDOffset+8], uint64(s.nextID))
	header.MarkDirty()
	return nil
}

func (s *Store) Insert(name, email string, age int32) (int64, error) {
	id := s.nextID
	pageNum, offset, err := recordLocation(id)
	if err != nil {
		return 0, err
	}
	record, err := encodeUser(User{ID: id, Name: name, Email: email, Age: age})
	if err != nil {
		return 0, err
	}
	page, err := s.pager.GetPage(pageNum, PageTypeData)
	if err != nil {
		return 0, err
	}
	copy(page.Data[offset:offset+RecordSize], record)
	page.MarkDirty()

	s.nextID++
	if err := s.persistNextID(); err != nil {
		s.nextID--
		return 0, err
	}
	return id, nil
}

func (s *Store) Get(id int64) (User, error) {
	if id < 1 || id >= s.nextID {
		return User{}, ErrNotFound
	}
	pageNum, offset, err := recordLocation(id)
	if err != nil {
		return User{}, err
	}
	page, err := s.pager.GetPage(pageNum, PageTypeData)
	if err != nil {
		return User{}, err
	}
	u, err := decodeUser(page.Data[offset : offset+RecordSize])
	if err != nil {
		return User{}, err
	}
	if u.Deleted {
		return User{}, ErrDeleted
	}
	if u.ID != id {
		return User{}, fmt.Errorf("record %d is corrupt: stored id is %d", id, u.ID)
	}
	return u, nil
}

func (s *Store) Scan() ([]User, error) {
	users := make([]User, 0, s.nextID-1)
	for id := int64(1); id < s.nextID; id++ {
		u, err := s.Get(id)
		if errors.Is(err, ErrDeleted) {
			continue
		}
		if err != nil {
			return nil, err
		}
		users = append(users, u)
	}
	return users, nil
}

func (s *Store) Delete(id int64) error {
	if _, err := s.Get(id); err != nil {
		return err
	}
	pageNum, offset, err := recordLocation(id)
	if err != nil {
		return err
	}
	page, err := s.pager.GetPage(pageNum, PageTypeData)
	if err != nil {
		return err
	}
	page.Data[offset+8] = 1
	page.MarkDirty()
	return nil
}

package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

func printUser(u User) {
	fmt.Printf("id=%d name=%s email=%s age=%d\n", u.ID, u.Name, u.Email, u.Age)
}

func main() {
	if len(os.Args) != 2 {
		fmt.Println("usage: minidb <database-file>")
		os.Exit(1)
	}

	store, err := Open(os.Args[1])
	if err != nil {
		fmt.Println("open error:", err)
		os.Exit(1)
	}
	defer store.Close()

	scanner := bufio.NewScanner(os.Stdin)
	for {
		fmt.Print("minidb> ")
		if !scanner.Scan() {
			fmt.Println()
			break
		}
		parts := strings.Fields(scanner.Text())
		if len(parts) == 0 {
			continue
		}

		switch strings.ToUpper(parts[0]) {
		case "INSERT":
			if len(parts) != 4 {
				fmt.Println("usage: INSERT <name> <email> <age>")
				continue
			}
			age64, err := strconv.ParseInt(parts[3], 10, 32)
			if err != nil {
				fmt.Println("age must be a 32-bit integer")
				continue
			}
			id, err := store.Insert(parts[1], parts[2], int32(age64))
			if err != nil {
				fmt.Println("insert error:", err)
				continue
			}
			fmt.Printf("inserted id=%d\n", id)

		case "GET":
			if len(parts) != 2 {
				fmt.Println("usage: GET <id>")
				continue
			}
			id, err := strconv.ParseInt(parts[1], 10, 64)
			if err != nil {
				fmt.Println("id must be an integer")
				continue
			}
			u, err := store.Get(id)
			if err != nil {
				fmt.Println("get error:", err)
				continue
			}
			printUser(u)

		case "SCAN":
			users, err := store.Scan()
			if err != nil {
				fmt.Println("scan error:", err)
				continue
			}
			for _, u := range users {
				printUser(u)
			}

		case "DELETE":
			if len(parts) != 2 {
				fmt.Println("usage: DELETE <id>")
				continue
			}
			id, err := strconv.ParseInt(parts[1], 10, 64)
			if err != nil {
				fmt.Println("id must be an integer")
				continue
			}
			if err := store.Delete(id); err != nil {
				fmt.Println("delete error:", err)
				continue
			}
			fmt.Printf("record %d deleted\n", id)

		case "STATS":
			st := store.Stats()
			fmt.Printf("pages=%d cached=%d cache_hits=%d disk_reads=%d disk_writes=%d validation_failures=%d\n",
				st.TotalPages, st.CachedPages, st.CacheHits, st.DiskReads, st.DiskWrites, st.ValidationFailures)

		case "FLUSH":
			if err := store.Flush(); err != nil {
				fmt.Println("flush error:", err)
				continue
			}
			fmt.Println("dirty pages sealed, checksummed, and flushed")

		case "VERIFY":
			pages, err := store.Verify()
			if err != nil {
				fmt.Println("verify error:", err)
				continue
			}
			fmt.Printf("verified %d pages\n", pages)

		case "PAGEINFO":
			if len(parts) != 2 {
				fmt.Println("usage: PAGEINFO <page-number>")
				continue
			}
			pageNum, err := strconv.ParseUint(parts[1], 10, 64)
			if err != nil {
				fmt.Println("page number must be a non-negative integer")
				continue
			}
			info, err := store.PageInfo(pageNum)
			if err != nil {
				fmt.Println("pageinfo error:", err)
				continue
			}
			fmt.Printf("page=%d type=%s generation=%d checksum=%08x\n",
				info.Number, info.Type, info.Generation, info.Checksum)

		case "HELP":
			fmt.Println("INSERT <name> <email> <age>")
			fmt.Println("GET <id>")
			fmt.Println("SCAN")
			fmt.Println("DELETE <id>")
			fmt.Println("STATS")
			fmt.Println("FLUSH")
			fmt.Println("VERIFY")
			fmt.Println("PAGEINFO <page-number>")
			fmt.Println("EXIT")

		case "EXIT", "QUIT":
			return

		default:
			fmt.Println("unknown command; try HELP")
		}
	}

	if err := scanner.Err(); err != nil {
		fmt.Println("input error:", err)
	}
}

22. What you should understand before leaving Part 3

Imagine the process starts and opens an existing three-page database. OpenPager first checks that the file length is divisible by 4096. The store asks for page 0 as metadata. The pager reads exactly 4096 bytes from offset 0. Before caching that page, it checks PG03, the physical header version, the page type, embedded page number 0, and the CRC-32. Only then does the store inspect the payload for MINIDB03, database version 3, page size, record size, page-header size, checksum algorithm, and nextID.

Now suppose the user requests ID 16. With 15 slots per data page, the store maps ID 16 to page 2, slot 0, byte offset 32 within the page. The pager reads file offset 2 × 4096 = 8192. It does not trust those bytes yet. It validates page 2's header and checksum and confirms its type is data. Only after that does decodeUser inspect bytes 32 through 287.

If a single byte at absolute offset 8233 was modified after the last valid flush, the recomputed CRC differs from the stored CRC. The pager returns a checksum error. The record decoder never receives that damaged payload.

If instead an intact copy of page 1 was written at page 2's physical position, the copied CRC can still be perfectly valid. But the embedded page number says 1 while the pager expected 2, so validation rejects it for the correct reason: the bytes may be internally intact, but they are in the wrong place.

When a record changes in memory, we do not immediately recalculate CRC. We mark the page dirty. At flush, we increment the page generation, calculate the checksum over the exact page image that is about to be written, store the checksum, write all 4096 bytes, and eventually call Sync. On a later read, that persisted checksum becomes evidence we can verify.

And finally, you should be able to state the limitation without hesitation: a checksum proves neither atomic transactions nor freshness across pages. If page 0 and page 2 are individually valid but represent different moments of an interrupted insert, Part 3 has no recovery protocol that can decide which database state to restore.

If that story feels natural, Part 3 worked.You no longer think of a database page as “4096 bytes we happened to read.” A persisted page now has identity, type, versioned structure, a write generation, and an integrity check—and the pager refuses to expose it until those invariants hold.

The pain that should now bother you

We can detect many damaged pages, but we cannot yet make related changes to several pages behave like one recoverable action. INSERT can dirty a data page and metadata page 0. A crash may persist one without the other. Both surviving pages may pass their checksums. That is the next reliability problem worth solving.

You started with pages the program blindly trusted. You ended with self-describing pages, format metadata, checksums, corruption detection, full-file verification, and a precise understanding of why recovery still requires more than CRCs.
